RemoteConnect project architecture

A single .NET project split into clean-architecture folders — one real UI implementation and one real domain model today, with named, empty boundaries waiting for WebRTC, signaling and native capture to land later.

Reference

Who does what

The files inside UI/Avalonia/ and Core/Device/ — everything else is an intentionally empty folder.

Program.cs

Configures and starts Avalonia — BuildAvaloniaApp().StartWithClassicDesktopLifetime(args).

UI/Avalonia/App.cs

The Application subclass. Registers the Fluent theme, creates MainWindow once the framework finishes initializing.

UI/Avalonia/MainWindow.cs

Builds the whole window in code — header, three-card content column, footer — plus the mock device list and DeviceType→icon mapping.

UI/Avalonia/AppTheme.cs

Every color and font as a named constant, so all custom controls stay visually consistent.

UI/Avalonia/Controls/*.cs

One class per visual piece — ModernButton, IconTextBox, IconBadge, IdChip, StatusBadge, RecentDeviceCard and the hand-drawn icon set.

Core/Device/DeviceConnection.cs

DeviceConnection, ConnectionStatus, DeviceType — zero dependency on Avalonia or any drawing type.
